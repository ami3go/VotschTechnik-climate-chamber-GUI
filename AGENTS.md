# AI agents — Vötsch climate chamber GUI

Repository: `ami3go/VotschTechnik-climate-chamber-GUI`.
The NiceGUI/web application must communicate with physical Vötsch chambers
**only** via `VotschTechnik-climate-chamber-Python` through the existing
VotschBackend/G04 services. Never duplicate the device protocol in the GUI.

## Physical HIL authorization (current policy)

- **PIN only** for agent-facing test authorization: ask for a local operator
  PIN generated by `bash scripts/hil_pin.sh setup`. Validity is 24 hours.
  No per-run signed permit, witness, private key or second authentication
  package should be requested for automated HIL **test tooling**.
- The operator issues or resets the PIN on the bench computer interactively.
  AI agents must **not** generate, reset, guess, persist or print a PIN,
  impersonate the operator, or disable/bypass validation.
- Run physical tests with `bash scripts/hil_pin.sh run -- COMMAND ...`
  after explicit operator handoff. Simulator/unit tests require no PIN.
- Always keep device serial pinning, approved temperature envelope,
  controller ownership, physical STOP readiness, STOP/UNKNOWN fault fencing,
  fresh telemetry, profile deadlines and append-only evidence. The PIN
  authorizes testing; it never authorizes unsafe setpoints, unattended
  intrusive fault injection, or bypass of a physical interlock.
- Every physical test must have a finite internal watchdog/deadline and
  final verified STOP/restore. Never substitute process termination for
  hardware STOP. For long software-only commands, use the standalone
  bounded watchdog in `scripts/h02_watchdog_command.py`.
- Do not commit credentials, PINs, private equipment addresses, HIL
  operator secrets or new physical test results without review.
- Legacy H02 signed permits still exist for an older **application runtime**
  path; do not claim that path has been changed without implementing and
  testing its admission changes. See `docs/HIL_PIN_RUNBOOK.md`.
