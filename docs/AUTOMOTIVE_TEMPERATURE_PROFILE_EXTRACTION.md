# Automotive temperature-profile extraction — source-traceable research matrix

> **Research date:** 2026-11-21. **Source catalogue:** [Automotive temperature-test standards](AUTOMOTIVE_TEMPERATURE_TEST_STANDARDS.md). **Coverage:** 86 standards/specifications; 16 LV 124 methods; detailed subtests/grade variants. **Status: research only — no profile is approved for physical execution.**

## Interpretation and evidence controls

A standard is not automatically a single temperature recipe. Test severity can depend on mounting category, selected test clause, DUT thermal mass, electrical state, cable/connector construction, component qualification grade, vehicle customer and the controlled revision. The index below accounts for **every one of the 86 entries** from the source catalogue without inventing numbers for unverified OEM clauses. Numeric rows are either verifiable from cited public content or explicitly identified as non-normative third-party examples.

**Evidence terms:** `VERIFIED_PUBLIC` = published standard/regulation excerpt or AEC text with numerics; `METHOD_PARAMETERIZED` = known test algorithm with required selections not yet fixed; `PUBLIC_VENDOR_EXAMPLE` / `MANUFACTURER_SPECIFIC_EXAMPLE` = secondary or device-specific example, **not** the OEM normative value; `METHOD_UNVERIFIED` = no dependable full severity. A reference of an LV method by several OEMs does not prove identical temperatures/durations across those OEMs.

**Do not execute imported profiles.** The JSON companion sets `execution_allowed: false` and every candidate `execution_approved: false`. A future application must validate and explicitly approve source revision, complete stage list, chamber measured capabilities under load, temperature tolerances, dwell-start criterion, DUT sensor, recovery, fault handling, interlocks, and an independent watchdog. The GUI must communicate through the existing Python chamber driver only; no bypass raw socket commands.

## C. Critical distinctions and exclusions

1. **ISO 16750-4:2023:** Fixed storage setpoints are −40 °C/24 h and +85 °C/48 h by default; powered operation uses selected `Tmin`/`Tmax`. Its small-DUT 30-cycle timed test (480 min/cycle without hot-soak) is a functional temperature test, **not** a general accelerated lifetime profile. Source: [ISO 16750-4:2023 preview](https://standards.theiteh.com/catalog/standards/iso/0ad163f0-0b86-48d9-ae0c-8a7a8497548d/iso-16750-4-2023).
2. **LV 124/VW/BMW/MB:** The public testing-service page has a repeated heading for K-01 where the second instance appears to describe K-02, and its K-01 figures are inconsistent. Values for K-02/K-03/K-05/K-08/K-09/K-14/L-02/L-03 are captured solely as **examples needing OEM clause verification**. Never silently populate a VW 80000, GS 95024 or MBN test from these numbers. Source: [test-service summary](https://www.eurolab.net/en/sektorel/otomotiv-testleri/otomotiv-icin-lv-124-testleri/).
3. **AEC-Q100 Rev J:** Grades 0/1/2/3 have distinct A4 cycling, A5 power-cycling, A6 HTSL, and B1 HTOL values. A4 requires JEDEC soak-mode/ramp choices; A5 power cycling is not the same as chamber air temperature cycling. Source: [AEC-Q100 Rev J PDF](https://api.eestar.com/article/share/2024/08/4cda620240826141050529.pdf).
4. **Battery regulation differences:** UN R100/R136 and AIS battery rules use ≥6 h at +60 and −40 °C, whereas **GB 38031-2025 pack shock uses 8 h per extreme** and GB cell cycling spans −40 to +85 °C with a detailed 480-min six-stage cycle. Battery tests need dedicated safety infrastructure. Source: [GB 38031 English copy](https://www.scribd.com/document/915222717/GB38031-2025-English-Version); [UN R100](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:42026X1695).
5. **Humidity tests:** IEC 60068-2-30:2025 has multiple 24-hour cycle variants with relative-humidity corridors, not a simple constant-RH recipe; dedicated RH control and dew-point detection are necessary. Source: [IEC sample](https://cdn.standards.iteh.ai/samples/iec/iec-60068-2-30-2025/47f7c7027dee4c17b4be867485a7d498/iec-60068-2-30-2025.pdf).
6. **Method-only references:** ISO/IEC/JEDEC test-method numbers, cable/connector standards and generic handbooks can be invoked with different severities. Filling every blank with −40/+85 °C would produce false compliance evidence.
7. **Facilities:** liquid immersion, splash water, solar irradiance, HAST/autoclave and power/thermal-shock apparatus cannot be emulated just by changing chamber temperature.

## D. Required fields before converting any row into a NiceGUI chamber profile

`standard_id`, `revision`, `clause`, `OEM/customer`, `DUT/temperature class`, `test selection`, `source/approval record`, `ordered stages` (`setpoint_c`, `transition_mode`, `ramp_rate/transfer_max`, `dwell_start=chamber|DUT_stabilized`, `dwell_s`, `RH_setpoint`, `DUT_state`, `functional checkpoint`), `repeats`, `recovery`, `measurement tolerance`, `acceptance class`, `chamber capabilities`, `watchdog heartbeat / timeout`, `safe abort/reconcile`, and `execution_authorization` are mandatory fields in a future generated test definition. Missing fields **must remain unset**, never default to room temperature or an arbitrary 1 °C/min ramp.

**Watchdog and execution security:** Each multi-hour test requires durable event logging, independent heartbeat, stalled-temperature and stalled-sensor detection, actual dwell timing from measured stabilization, power-loss state reconciliation, and fail-safe abort. Offline emulator runs are unrestricted by HIL authorization, but genuine energized chamber tests follow the project PIN-based approval and physical interlocks.
